# Code audit and verification — 19 September 2026

The received Python backend was reviewed, corrected and exercised across its
three modelling levels, spreadsheet companion and inverse energy-signature
fitter. Physical heat-balance equations, example datasets, workbook and embedded
Model 3 golden results were retained. The folder contains no Git metadata and
does not include the historical reports/archives linked by earlier documentation.

## Corrected defects

| Finding | Correction and regression evidence |
|---|---|
| A leap-year configuration assigned an 8,760-hour file to a leap-year clock, shifting dates after February and losing the final day | Reject leap-year requests in shared configuration, EPW ingestion and schedule expansion; do not imply full leap-year support |
| Arbitrary timestep counts were rounded to whole minutes while the solver used 3,600/n seconds | Require a positive integer divisor of 60; test timestamp spacing, annual length and final timestamp |
| Non-divisor azimuth counts generated different bin names from the lookup | Use the same integer-degree bin centres in generation and lookup; test every compass degree with seven bins |
| Consumed EPW missing codes/non-finite values and reordered hours could enter the solver | Validate consumed weather fields, location and month/day/hour sequence, with field/line diagnostics |
| String toggles, invalid initial conditions, incorrect power signs and invalid simplified modes could fail late or be interpreted incorrectly | Validate shared configuration before preprocessing and create CLI output only after configuration construction |
| A truncated CSV row converted a missing required cell into the literal string `None` | Treat missing cells as empty and report their source row |
| Building names and IDs were incorporated directly into CLI filesystem paths | Generate bounded names with identity hashes and record detail paths in the manifest; preserve original identities in tables |
| Simplified detail files used a placeholder weather ID, inconsistent with summary output | Use the same weather-content hash throughout the CLI run |
| Irrelevant CLI options were silently ignored | Reject `--model` outside dynamic and `--zone-mode` outside simplified |
| Non-finite validation observations could abort a portfolio fit during metric calculation | Exclude/count non-finite and negative energy observations; preserve calibration/validation separation |
| Empty inverse datasets failed indirectly; all-failed reports had uninformative prediction exports/status | Explicit empty-input errors, stable prediction headers, and complete/partial/failed report status |
| Long/sanitization-colliding 5P filenames and source-run conflation affected reports | Bounded hashed filenames; distinguish source type, source ID and source run when plotting; reject unsafe report run IDs |
| Verification workers could record solver failures while returning process success | Propagate worker failures and test failures to nonzero exit codes |
| Workbook verification only exported values | Require 156 reproduction PASS results and scan all sheets for formula errors; record workbook hash without modifying it |

These changes strengthen the documented execution paths. They are not a claim
that every low-level class validates all possible manually constructed inputs.

### Performance

The 5P solver now accepts a full-rank, positive unconstrained least-squares
solution directly and otherwise retains active-set enumeration. This avoids
six unnecessary small solves for admissible interior solutions. CLI input
files are also hashed once per run instead of twice.

Seven repeated fits per synthetic case, median wall time on this machine:

| Monthly response | Before | After | Fit speedup |
|---|---:|---:|---:|
| Heating and cooling | 53.34 ms | 18.58 ms | 2.87× |
| Heating only | 55.17 ms | 40.45 ms | 1.36× |
| Constant demand | 57.91 ms | 57.41 ms | 1.01× |

Predictions matched within `rtol=1e-12, atol=1e-10`. These timings describe the
inverse fit, not the forward engines or a deployed web service. No forward
solver speedup is claimed. Raw values and fitted parameters are retained in
the benchmark evidence.

## Compatibility and next work

Detail filenames now follow a safe ID/hash scheme. Consumers must use
`manifest.building_outputs` rather than construct filenames from display names.
Invalid settings that were previously accepted may now fail early, including
leap years and timestep counts such as seven per hour. Common monthly/annual
energy columns and model equations are unchanged.

See [input contracts](data_contracts.md), [the dataset tutorial](input_dataset_tutorial.md)
and [development guidance](development.md). Remaining priorities are complete
schemas for envelope/schedule/system libraries, measured-data validation,
resource-bounded web jobs, 10/100/1,000-building performance evidence and
explicit scientific review of cooling, AHU, initial-state and ground assumptions.
